## Review 任务要求

- 【必须】逐条回答以下问题：
    - 【Review】的对象解决了什么问题？又带来了什么问题？是否存在备选方案？
    - 代码是否符合【代码要求】？文档是否符合【文档要求】？它们是否符合最佳实践？
    - 是否存在重复的代码和文档？
    - 代码和文档的描述是否一致？
    - 代码的命名风格是否一致？命名是否合理？
    - 文档的术语和风格是否一致？
    - 代码和文档是否有提升的空间或【Refactor】的机会？

## 提交规范

- 【应当】遵循 Conventional Commits（如：`feat: ...`、`fix: ...`、`refactor: ...`）。
- 提交信息【不应】超过三行：
    - 第一行为简洁英文 subject。
    - 后续一到两行为简短补充；更详细说明【应当】放在 MR/PR 或文档中。

## Commit 任务要求

- 【必须】对变更的内容进行【Review】，总结变更范围和影响。
- 【必须】按照【提交规范】编写 commit message。
- 【必须】在无需我再确认的前提下，一次性生成和执行 one-liner 命令（如 `git add . && git commit -m "..." && git push`），默认提交所有变动文件，由我在 IDE 中批准执行。
